# Counting Rules v1

## Status

Version: 1.0.0  
Label status: PROVISIONAL — independent human review required before V0.1 release.

Synthetic fixtures are pinned by fixture version and SHA-256 content fingerprint.
External fixtures are also pinned by upstream commit.

## Symbols

Count:

- each Python module, including package `__init__.py`,
- each class,
- each synchronous or asynchronous function,
- each method,
- each nested function,
- each module-level constant whose name is uppercase,
- each deterministically bound framework route.

A route handler produces both its ordinary function symbol and a separate
`ROUTE` record. The route record identity is
`(module, handler, HTTP method, normalized path)`.

Do not count lambdas, comprehension targets, parameters, local variables,
imported names, or re-exports as new symbols.

A decorated symbol's source span begins at its `def` or `class` keyword, not
its decorator line. Decorators are recorded as symbol metadata with their own
source location, not as span content.

## Imports

Count one import edge per `(source_unit, imported_name)` pair.

```python
from a import b, c
```

produces two edges. Aliases preserve the canonical imported name and record the
local alias separately.

Imports under `if TYPE_CHECKING:` are labelled `type_checking=true` and are not
part of the V0.1 import-recall denominator. Dynamic `importlib` targets are
unresolved references, not ordinary static import edges.

`source_unit` is the normalized cross-language field. For Python it identifies a
module; for JavaScript or TypeScript a module/file; and for Java, Go, or C# the
language-appropriate package/module plus file identity. Language adapters
normalize into this schema without discarding language-specific evidence.

## Re-exports

A name in `__all__` that was imported from another module creates an `EXPOSES`
relationship to the original symbol. It does not create another symbol.

## Source spans

Lines are one-based and inclusive. Columns are zero-based and end-exclusive.
A span must refer to content in the pinned fixture snapshot.

## Questions

Questions are labelled with:

```text
query_class
answerable
required_slots
essential expected claims
optional expected claims
expected resources
expected behavior
```

A question is answerable only when its essential claims can be supported from the
repository snapshot.

## Material claims

An essential claim is required to answer the question. An optional claim adds
useful detail but can be removed without making the answer non-responsive.

Unsupported essential claims require abstention. Unsupported optional claims are
removed and reported as gaps.

## Review procedure

Two engineers independently review every provisional label. Disagreements are
adjudicated and this document is clarified. Agreement statistics and reviewer
identities are recorded in `review.json`; they must never be fabricated.
